## Upload with GitHub CLI

Run these commands from the project directory after reviewing the files you intend
to publish. `gh` is installed in the environment used for this review.

1. Sign in. Follow the browser instructions; never put a token in a project file.

   ```bash
   gh auth login
   gh auth setup-git
   ```

2. Check your commit identity. If missing or incorrect, set a repository-local
   name and email with `git config user.name "Your Name"` and
   `git config user.email "YOUR_GITHUB_NOREPLY_EMAIL"`. Copy the actual no-reply
   address from GitHub **Settings → Emails** if you prefer to keep your email private.

   ```bash
   git config user.name
   git config user.email
   ```

3. Stage the reviewed source files. The explicit list helps keep local files out.

   ```bash
   git add .gitignore .streamlit/config.toml README.md LICENSE NOTICE THIRD_PARTY_NOTICES.md MANIFEST.in app.py pyproject.toml uv.lock photosigning/ tests/ docs/ third_party/ ui-preview.png
   git diff --cached --stat
   git diff --cached --check
   git diff --cached
   ```

   Review the staged diff before continuing. Do not add `.venv`, `.photosigning`,
   private keys, downloaded models, personal photos, or secret configuration.
   `.gitignore` cannot protect files already tracked or deliberately force-added.

4. Create the first commit and publish a new public repository. The final command
   makes the staged project publicly accessible. Choose an unused repository name;
   use `YOUR_ACCOUNT/photosigning` if you need to specify the owner explicitly.

   ```bash
   git commit -m "Initial open-source release"
   git branch -M main
   gh repo create photosigning --public --source=. --remote=origin --push
   gh repo view --web
   ```

   On GitHub, confirm that the README, Apache-2.0 license, NOTICE, and third-party
   notices appear and that private local files are absent.

## Alternative: create the repository on GitHub's website

Complete the local staging and commit steps above. Create a new public repository
at [github.com/new](https://github.com/new), leaving the **Add README**, **Add
.gitignore**, and **Choose a license** initialization options empty because these
files already exist locally. Authenticate Git using GitHub CLI, a credential
manager, or SSH; your GitHub account password cannot authenticate an HTTPS push.
Then replace `YOUR_USERNAME` below with your account name and run:

```bash
git remote add origin https://github.com/YOUR_USERNAME/photosigning.git
git push -u origin main
```

Use either this method or `gh repo create`, since both create the `origin` remote.
These steps assume the repository still has no remote. They follow
[GitHub's official local-project upload guide](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github).
